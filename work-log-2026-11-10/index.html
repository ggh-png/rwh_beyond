2026-11-10 GraspGenX·ROS Bridge·BT 집기 통합¶

구현 내용¶

  • 추론 전용 Dockerfile/Compose, 공식 소스 버전 고정, checkpoint/cache/TRT/log 영속화, health check 및 로컬 rootless Podman GPU 실행 스크립트를 추가했다.
  • 로컬 RTX 3060에서 실제 piper_hand 모델 추론 → ZMQ → ROS Action 후보 수신을 확인했다. 공식 2048점 샘플의 100개 생성/상위 20개 요청에서 후보 20개와 점수 수신, CLI 전체 약 1.27초, 관측 VRAM 약 1 GB였다. 단일 조건의 측정이며 일반 성능 보장은 아니다.
  • rwh_beyond_msgs에 InferGrasps/RunGraspStep/GraspCandidate를 추가하고 rwh_beyond_grasp_bridge에 입력 변환, 행렬 검증, timeout/cancel/동시 요청 처리를 구현했다.
  • 빨간색 RGB 마스크 → Depth 역투영 → 객체 XYZ → 실제 모델 후보 → 촬영 시각 TF/TCP 보정 → IK/충돌/경로 검사 → 접근/접촉 확인/리프트 흐름을 MuJoCo 전용으로 구현했다.
  • GraspStep/MoveObservation BT 플러그인과 Groot2 모델을 추가했다. 추론은 prepare에서만 수행한다. attach는 실제 접촉 확인 후 MoveIt scene에 등록하며 MuJoCo에서 강제로 물체를 고정하지 않는다.
  • ros_runner 의존성은 bt_demo → grasp_bridge → piper_sim이다. runner는 ROS 프로세스만 관리하며 GPU 모델은 별도로 기동한다.
  • moma-mj-lab에 색상 기반 대상 점 제외, 물리 접촉/높이 검증 서비스, 성공한 닫기 명령 유지와 RViz 표시를 추가했다.

운영 상태와 범위¶

모델 컨테이너는 tini/sleep infinity로 유지하고 start_server.sh를 exec로 따로 실행한다. Ctrl+C로 모델만 종료할 수 있다. 상태는 health로 확인하며 실행 여부를 문서의 고정값으로 가정하지 않는다. 운영 명령과 전체 BT 설명을 참고한다.

현재 저장된 demo.xml은 MoveObservation이 주석 처리되고 마지막 MoveHome이 추가된 사용자 구성을 보존했다. 관측 자세를 포함한 이전 트리에서 상자 약 7–8 cm 상승, 취소 복원·재실행·이미 든 상태의 goal 차단을 검증했다. 현재 트리의 관측 생략과 마지막 홈 복귀를 포함한 전체 집기는 이번 문서 정리에서 재실행하지 않았다. 장시간 파지 안정성 튜닝은 범위를 확대하지 않았다. 내려놓기/실물 동작은 미구현이다.

원격 RTX 5090 서버는 SSH 진단만 완료했으며 Docker/sudo 권한에서 차단된 상태다. 호스트 설정 변경이나 원격 모델 실행은 수행하지 않았다. 로컬 성공과 원격 미검증을 구분한다.

커밋 전 재검증¶

기존 로봇 컨테이너에서 실행했으며 실제 로봇 이동이나 새 집기 goal은 보내지 않았다.

cd src/rwh_beyond

세 관련 레포의 git diff --check도 통과했다. GPU 추론·물리 집기의 이전 검증 명령과 제한은 빨간 상자 파지, 초기 구축·측정은 GraspGenX 통합 기록에 정리했다.

SAM 3 서버·RGB-D 분할 확장¶

  • 별도 rwh-sam3-local idle 컨테이너와 공식 소스 고정 이미지, 영속 저장소, localhost ZMQ 분할 서비스(5567), Docker Compose/Podman 운영 명령을 추가했다.
  • InferGrasps에 RGBD 입력·텍스트/박스·객체 선택 픽셀과 분할 결과 마스크/점수를 추가했다. SAM은 GPU 서버에서 실행하고 Depth 역투영은 기존 ROS CPU 코드를 재사용한다.
  • 마스크에서 얻은 XYZ를 기존 GraspGenX(5566)로 보내며, 다중 객체는 기본적으로 거부한다. mock 결과는 명시적 테스트 설정에서만 허용하고 color fallback은 자동 사용하지 않는다.
  • BT prepare/runner를 연결하고 관측 점군·수평 지지면 기반 충돌 크기 추정, 선택 객체 AABB 기반 Octomap 제외·실패/취소 시 복원을 추가했다.
  • SAM 공식 import/CUDA 인식, Bridge/runner 49 tests + 3 subtests, 서버 선택 로직 3 tests, MuJoCo 4 tests, BT/navigator 검사와 문서 빌드를 통과했다.
  • 사용자 직접 HF 로그인은 성공했지만 sam3.pt 다운로드는 GatedRepoError 403이었다. 모델 접근 승인은 확인되지 않았다. 실제 SAM 분할·VRAM/지연 측정과 SAM을 포함한 전체 집기 성공은 아직 검증하지 않았다. 인증정보·가중치는 Git에 포함하지 않는다.
  • 기존 색상 기반 GraspGenX 집기 성공 기록과 새 SAM 경로의 검증 상태를 구분한다. 새 모델 경로의 실제 로봇 실행은 지원하지 않는다.

자세한 SAM 3 운영·입력·제한·검증 기록을 참고한다. Action 타입과 SetGraspRegion 서비스 변경으로 세 관련 레포를 함께 업데이트·빌드하고 기존 Action 서버·클라이언트와 runner를 재시작해야 한다.

SAM 3 가중치 승인 후 실제 실행¶

공식 모델 접근과 fine-grained 토큰의 public gated repo 읽기 권한을 확인한 후 sam3.pt를 다운로드했다. 토큰은 사용자 숨김 입력/개인 캐시에만 저장했다. 실제 SAM 모델 health와 GPU 인식을 확인했다.

  • MuJoCo RGB-D 320×240에서 red box/cube 텍스트로 실제 mask 생성.
  • RGBD Action → SAM mask → 실측 XYZ → GraspGenX 후보 20개 수신 약 1.06초.
  • GPU 관측: SAM 약 5480 MiB, GraspGenX 약 1002 MiB. 정확한 peak는 아니다.
  • TF 도착 race는 정확한 촬영 시각을 보존한 2초 timeout 대기로 수정했다.
  • 독립 domain baseline BT: 실제 양쪽 접촉과 7 cm 이상 상승 성공.
  • runner 자동 기동·준비 중 취소/영역 복원·재실행 리프트·보유 중 재goal 차단·종료 성공.
  • 사용자 원본 BT XML은 유지했다. 검증용 baseline은 관측 자세를 켜고 마지막 홈 복귀를 제외했다. 장시간 안정성, 실물, 복수 객체 성공률, 사용자 원본 트리 전체는 미검증이다.
  • Bridge/runner 49 tests와 시뮬레이터 4 tests 재통과. 문서 빌드·diff 검사 통과.

실제 모델·BT·runner 상세 기록과 JSON/마스크 이미지를 추가했다. GPU 모델은 실행 상태로 유지하고 테스트 ROS 프로세스는 정리했다.

SAM 마스크 → 로컬 점군 → GraspGenX를 BT 단계로 분리¶

사용자가 요청한 최종 데이터 경로를 BT에 명시했다. GraspStep의 segment_target은 RGB를 SAM으로 보내 마스크를 받고, build_object_cloud는 로봇 PC ROS CPU에서 같은 Depth/K를 역투영해 PointCloud2를 먼저 발행한다. prepare는 그 점군을 POINT_CLOUD Action으로 보내 GraspGenX 추론·후보 검사를 한다. 별도의 RGBD 편의 Action도 유지한다.

  • 관측 30초 만료 및 팔 관절 변화 시 재관측을 요구한다. 실패/취소 시 관측 context 정리.
  • 기본 demo.xml에 위 두 단계를 추가하고 MoveObservation을 활성화했다. 마지막 홈 복귀 유지.
  • baseline에서 로컬 점군 2780점 → 추론 시작 순서와 실제 파지/리프트 성공.
  • 전체 기본 트리에서 2783점 → 약 7.6 cm 리프트 → 홈 복귀, 양쪽 접촉 유지 성공.
  • 한 전체 트리 시도는 관측 이동 전 START_STATE_INVALID로 중단돼 실패 기록도 보존했다. 해당 시도에서 SAM/점군 단계는 실행하지 않았으며 충돌 검사는 해제하지 않았다.
  • Bridge/runner 단위·통신 검사 52 tests와 3 subtests 통과.
  • mesh는 만들지 않았다. GraspGenX의 XYZ 입력을 사용하며 완전한 뒷면 형상 복원은 보장하지 않는다.

실측 수치와 실패를 포함한 기록은 SAM 로컬 점군 실험에 정리했다. 원격 공용 GPU 서버 배포와 실물 로봇 동작은 이번 실험 범위가 아니다.

추가 runner에서는 취소/복원과 재실행 리프트 후 5초 유지 시 물체가 미끄러졌다. 다른 시작 시도는 lifecycle get_state 요청 실패로 중단됐다. 전체 트리 성공 실험과 분리해 기록했으며 장시간 파지 튜닝을 범위 밖으로 유지했다. 로컬 XYZ를 PLY/NPY로 저장하고 동일 점군으로 실제 서버 후보 반환도 확인했다.
