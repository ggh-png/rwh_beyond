    BT 플러그인별 기능과 포트¶

    현재 등록 노드는 16개입니다. 촬영·인식 4개, 모션·장면 11개, 지도 초기화 1개로 구성됩니다. 실행 순서는 BT 실행 흐름, 프로세스 경계는 BT와 실행 구조를 참고하세요. 입력 → 출력의 이름은 XML 포트이며 {이름}은 Blackboard 키입니다.

    라이브러리와 구현 위치¶

    라이브러리 노드 수 구현
    rwh_beyond_perception_bt_nodes 4 plugins/action/perception_actions.cpp
    rwh_beyond_motion_bt_nodes 11 plugins/action/motion_actions.cpp, 공통 연산·통신은 src/motion_context.cpp
    rwh_beyond_clear_octomap_action_bt_node 1 plugins/action/clear_octomap_action.cpp
    rwh_beyond_bt_nodes 전체 로더 src/register_nodes.cpp; 위 3개 라이브러리를 등록

    경로는 rwh_beyond_bt/ 기준입니다. 모션 노드들은 BT 내부의 MotionContext를 공유합니다. 별도 coordinator 프로세스나 /grasp/* 단계 중계 액션 서버는 없습니다.

    문서를 읽는 기준¶

    플러그인은 XML에 적힌 BT 노드 타입입니다. 예를 들어 MoveHome은 한 타입이지만 집기 시작과 복귀에 서로 다른 인스턴스로 배치됩니다. Sequence는 프로젝트 플러그인이 아니라 BehaviorTree.CPP의 제어 노드입니다. 한 자식이 성공해야 다음 자식을 tick하며, 실행 중인 자식은 RUNNING, 실패한 자식은 전체 Sequence의 FAILURE로 전파됩니다.

    구현 방식 해당 노드 tick 중 동작
    StatefulActionNode CaptureRgbd, ClearOctomap 시작 시 수신·요청을 준비하고 다음 tick마다 완료를 확인
    Nav2 BtActionNode SegmentObject, InferGrasps ROS 액션 goal 전송, 결과 대기, 실패·취소 전달
    SyncActionNode BuildObjectCloud 한 번의 tick에서 점군 계산 후 성공 또는 실패
    공통 MotionAction 나머지 모션·장면 11개 시작 tick에서 입력을 읽고 비동기 작업 실행, 후속 tick에서 결과 확인

    SUCCESS는 각 노드의 완료 조건을 충족했다는 뜻입니다. 계획 성공은 팔 이동 완료와 다르고, 장면 부착 성공은 실제 잡힘을 센서로 확인했다는 뜻과 다릅니다. 아래 내부 순서는 각 노드가 수행하는 처리이며 XML에 따로 추가할 하위 플러그인이 아닙니다.

    준비·지도·관측 이동¶

    CheckGraspReady¶

    • 입력: release_previous (기본 false). 출력 포트 없음.
    • 기능: 최신 관절 피드백, 실물 전송 준비, Planning Scene의 부착 상태, SAM·모델 health, IK·FK·계획·Cartesian·실행·그리퍼 인터페이스 준비를 확인합니다.
    • 직접 호출: /get_planning_scene, /sam3/health, /graspgenx/health. 실물에서는 /grasp/hardware_transport_ready의 physical_feedback_transport 응답도 확인합니다.
    • 부착 처리: false이면 기존 대상이 부착된 상태에서 새 pick을 거부합니다. true이면 현재 위치에서 그리퍼 개방·부착 해제·정리 후 진행합니다. 알 수 없는 부착 물체는 거부합니다.
    • 촬영은 수행하지 않습니다. 실제 RGB-D 획득은 뒤의 CaptureRgbd가 담당합니다.

    내부 순서와 완료 조건. 최신 피드백을 최대 5초 기다린 뒤 로봇 모델·관절 한계와 전송 경로를 확인하고, Planning Scene의 실제 부착 정보를 내부 상태와 맞춥니다. 이전 대상을 놓도록 지정했다면 이 시점에 개방·해제를 수행하고, 이후 모델 health 응답과 모션 인터페이스 준비를 확인합니다. 이 노드의 성공은 이후 요청을 보낼 준비가 됐다는 의미이며, 목표 물체가 영상에 있는지나 집을 수 있는지는 뒤의 인식·선택 단계가 판단합니다.

    실패를 볼 때. 오래된 피드백, 실물 transport 응답 실패, 알 수 없는 부착 물체, 모델 health 실패, MoveIt·그리퍼 준비 시간 초과를 구분해 확인합니다. release_previous=true는 단순 상태 초기화가 아니라 실제 개방 명령을 포함합니다.

    ClearOctomap¶

    • 입력: once=true, timeout=30.0초, fresh_clouds=2, service_name=/clear_octomap, cloud_topic=/camera/depth/filtered_points, scene_service=/get_planning_scene. 출력 포트 없음.
    • 기능: clear를 한 번 요청한 뒤 clear 이후의 서로 다른 비어 있지 않은 점군과 다시 생성된 Octomap을 확인합니다. once=true는 해당 노드 인스턴스의 첫 성공 이후 생략합니다.
    • 직접 호출: std_srvs/srv/Empty, moveit_msgs/srv/GetPlanningScene.
    • 공통 octomap_enabled=false이면 성공으로 건너뜁니다. 기본 집기 XML은 once=false로 두 번 호출합니다.
    • 취소 시 이미 전송한 Empty 서비스는 되돌리지 않으며, 지도 준비 완료로 표시하지 않습니다.

    내부 순서. SERVICES → CLEAR → CLOUDS → SCENE으로 진행합니다. clear와 scene 서비스가 준비되면 clear를 한 번만 보내고, 응답 이후 시각보다 새로운 점군 timestamp를 셉니다. 필요한 점군 수가 모이면 Octomap을 조회합니다. 지도가 아직 비어 있으면 새 점군을 더 기다린 뒤 다시 조회합니다.

    성공과 실패. clear 응답만 받았다고 성공하지 않으며, 재생성된 비어 있지 않은 지도까지 필요합니다. 실패 코드는 입력 오류 INVALID_INPUT, 전체 시간 초과 OCTOMAP_TIMEOUT, 서비스 예외 OCTOMAP_SERVICE_ERROR입니다. once는 같은 XML에 있는 다른 ClearOctomap 인스턴스와 공유하지 않으며, halt는 이미 전송한 clear를 취소하지 못합니다.

    MoveHome¶

    • 입력: 선택적 home_joint_positions (joint1~6 순서의 유한한 rad 6개).
    • 기능: 현재 피드백에서 home까지 충돌 검사 관절 경로를 계획·실행합니다. 이미 home_joint_tolerance 안이면 실행을 생략합니다.
    • 직접 호출: Planning Scene 확인, /plan_kinematic_path (GetMotionPlan), /execute_trajectory (ExecuteTrajectory).
    • XML 생략 시 bt_motion.home_joint_positions를 사용합니다. 들고 있는 대상의 충돌 형상은 유지합니다.
    <MoveHome home_joint_positions="0;0;0;0;0;0"/>

    내부 순서. 전송·부착 상태를 확인하고 현재 관절값을 home과 비교합니다. 이동이 필요하면 현재 로봇 상태에서 arm 6축만 home 값으로 바꾼 목표 상태를 만들고, 충돌 검사 계획을 받아 실행합니다. 실행 결과 이후에도 실제 관절 피드백으로 home 도착을 확인합니다.

    완료와 주의점. 성공은 home 허용 오차 안에 도착했다는 뜻입니다. 이 노드는 그리퍼를 열지 않으므로 집기 후 복귀에서도 물체를 유지합니다. 계획 실패, 실행 거부, 피드백 도착 시간 초과는 모두 실패입니다.

    OpenGripper¶

    • 입력: 선택적 opening (전체 간격 0~0.10m), duration (0.001~30초).
    • 기능: 지정 폭으로 열고 피드백이 목표 폭에서 5mm 이내인지 확인합니다.
    • 직접 호출: /gripper_controller/follow_joint_trajectory (FollowJointTrajectory).
    • 생략 시 bt_motion.gripper_open_width (현재 0.10m), 3초입니다. 부착된 대상이 있으면 자동 개방을 거부합니다. 배치 후 개방은 ReleaseObject를 사용합니다.

    내부 순서. 부착 여부를 먼저 검사하고 gripper 관절 하나의 궤적을 보냅니다. 컨트롤러의 성공 결과를 받은 뒤 최대 10초 동안 실제 간격이 목표와 5mm 미만 차이가 되는지 기다립니다.

    완료와 주의점. 성공하면 다음 관측·집기 준비로 진행할 수 있습니다. 액션 성공만으로 개방 완료를 판정하지 않습니다. 부착 상태에서 실패하는 것은 잘못된 호출 순서를 막는 검사이며, 그 상태를 해제하려면 배치 후 ReleaseObject 흐름을 사용합니다.

    MoveObservation¶

    • 입력: 선택적 home_joint_positions, x, y, z, tilt_deg, settle_time.
    • 기능: 설정된 home 관절값의 FK를 계산하고, 그 TCP에 base 축 위치 오프셋과 home 로컬 회전을 적용한 목표까지 Cartesian 이동합니다. 이후 센서 안정화 시간을 기다립니다.
    • 직접 호출: /compute_fk (GetPositionFK), /compute_cartesian_path (GetCartesianPath), /execute_trajectory.
    • X·Y·Z 허용 범위는 각각 -0.30~0.30m, tilt_deg는 -90~90°이며 Y 기울임만 덮어씁니다. settle_time은 0~30초입니다. X·Y 기본값은 0, 나머지는 YAML에서 읽습니다.
    • 물체를 들고 있지 않으면 먼저 home에 있어야 합니다. 부착 상태에서는 복귀용으로도 사용합니다. 호출할 때마다 home 기준으로 계산하며 현재 위치에 오프셋을 누적하지 않습니다.
    <MoveObservation x="0.0" y="0.0" z="0.10" tilt_deg="40.0" settle_time="0.5"/>

    목표를 만드는 방법. 먼저 home 관절 상태의 FK로 기준 TCP를 구합니다. 위치는 base 축으로 (x,y,z)를 더하고, 방향은 home 로컬 기준 RPY 회전을 합성합니다. XML의 tilt_deg는 RPY 중 Y만 바꾸므로 YAML의 X·Z 회전 설정도 함께 확인해야 합니다.

    실행과 완료. 현재 관절 상태에서 이 목표로 완전한 Cartesian 경로를 계획·실행하고, settle_time을 기다린 뒤 성공합니다. 같은 노드를 두 번 실행해도 오프셋을 두 번 더하지 않습니다. 물체가 없는데 home이 아니거나 Cartesian이 불완전하면 실패하며, 이 노드 자체는 촬영하지 않습니다.

    촬영·분할·점군·모델¶

    CaptureRgbd¶

    • 입력: timeout=10.0초 (0 초과~30초).
    • 출력: capture (Observation: 불변 RGB·Depth·CameraInfo·관절값·ID 묶음), observation_id (문자열).
    • 기능: 노드 시작 시점보다 새로운 같은 timestamp의 RGB·정렬 깊이·보정 정보를 기다립니다. 해상도·optical frame 일치와 1초 이내 수신한 유한한 arm 6축 관절값도 확인합니다.
    • 구독: camera/color/image_raw, camera/depth/image_rect_raw, camera/depth/camera_info, feedback/joint_states. 영상 토픽은 bt_perception.rgb_topic/depth_topic/info_topic으로 변경할 수 있습니다.
    • 모델·MoveIt을 호출하지 않습니다. 취소 시 미완성 촬영 묶음을 비웁니다.

    내부 순서. 시작 시 수집 버퍼를 초기화하고 시작 시각보다 새로운 프레임만 대상으로 삼습니다. RGB·Depth·CameraInfo를 같은 timestamp로 묶고, 동일한 영상 크기·optical frame과 최신 6축 관절값이 갖춰지면 불변 관측 객체를 Blackboard에 씁니다. 관측 ID는 프레임 timestamp에서 생성합니다.

    완료와 실패. 성공한 관측은 뒤의 SAM·역투영·후보 선택이 공유하는 기준입니다. 동기화되지 않은 영상이나 오래된 관절값은 기다리다가 timeout이 되고, 등록된 영상의 크기·frame 불일치는 실패합니다. 카메라 연결만으로 성공하지 않습니다.

    SegmentObject¶

    • 입력: capture, 선택적 target_text.
    • 출력: mask (sensor_msgs/Image).
    • 기능: RGB와 텍스트·박스·선택점 조건을 SAM 브릿지에 보내고 원본 영상에 대응하는 마스크를 받습니다. 기본적으로 mock 분할 결과를 거부합니다.
    • 직접 호출: /segment_image (rwh_beyond_msgs/action/SegmentImage).
    • 대상 우선순위는 /run_demo.target_text → XML target_text → launch 대상 override → YAML 기본값입니다. 박스·선택점·선택 정책은 bt_perception에서 읽습니다. 현재 정책은 highest_score입니다.
    • 표시용 잘린 이미지가 아니라 깊이 픽셀 선택에 사용할 이진 마스크를 출력합니다. BT의 결과 대기는 70초이며 취소를 브릿지에 전달합니다.

    내부 순서. 관측의 RGB를 그대로 사용해 target text 우선순위를 적용하고, YAML의 box·selection point·selection policy를 액션 goal에 채웁니다. SAM 성공 결과와 mock 허용 여부를 검사한 후 object_mask로 연결할 마스크를 출력합니다.

    완료와 실패. 액션 goal 거부·서버 중단·70초 결과 시간 초과·mock 거부는 실패입니다. 마스크와 깊이의 정합성은 다음 BuildObjectCloud에서도 검사합니다. 대상을 바꿔 실행하려면 /run_demo.target_text를 지정할 수 있으며, 요청 값은 XML 값보다 우선합니다.

    BuildObjectCloud¶

    • 입력: capture, mask.
    • 출력: cloud (sensor_msgs/PointCloud2: 카메라 좌표계, XYZ float32, m).
    • 기능: 마스크·깊이·보정의 좌표계·시각·크기를 검사하고 유효 깊이 픽셀을 역투영합니다. 16UC1은 mm, 32FC1은 m로 읽으며 패딩·엔디언·지원되는 plumb_bob 왜곡을 처리합니다. 유효 점 100개 이상을 요구하고 최대 200000개로 줄입니다.
    • ROS 호출: 외부 서비스·액션 없음. BT 내부 CPU 연산입니다. /grasp/object_cloud에 같은 점군을 디버그용으로 발행합니다.
    • 이 단계가 실패하면 모델 추론은 실행하지 않습니다.

    기하 처리. 마스크가 선택한 픽셀 중 유효한 깊이를 골라 내부 파라미터로 XYZ를 복원합니다. 개념적으로 X=(u-cx)Z/fx, Y=(v-cy)Z/fy이며, 지원하는 왜곡 보정을 함께 적용합니다. 출력은 카메라 optical frame의 점군이므로 base 변환은 후보 선택 단계까지 미룹니다.

    완료와 실패. 최소 점 수를 충족하면 Blackboard 출력과 디버그 발행을 마치고 성공합니다. 지원하지 않는 인코딩·왜곡, 잘못된 저장 크기·frame·stamp, 점 수 부족은 실패입니다. 디버그 토픽 구독자가 없어도 계산 결과는 다음 노드로 전달됩니다.

    InferGrasps¶

    • 입력: cloud.
    • 출력: candidates (GraspCandidate[]: 모델 파지 PoseStamped·점수).
    • 기능: POINT_CLOUD 모드와 piper_hand 그리퍼로 모델을 호출합니다. 현재 YAML은 num_grasps=1000, top_k=500입니다. 성공 응답·OK: 메시지·비어 있지 않은 후보를 요구합니다.
    • 직접 호출: /infer_grasps (rwh_beyond_msgs/action/InferGrasps). BT의 결과 대기는 70초입니다.
    • 후보 좌표계·timestamp는 입력 점군을 따릅니다. 여기서는 최종 실행 TCP나 접근 궤적을 결정하지 않습니다.

    SegmentObject·InferGrasps는 Nav2 액션 클라이언트의 server_name·server_timeout 포트도 사용합니다. 기본 XML의 server_timeout="1000"은 목표 요청 응답 대기 1000ms이며 모델 추론 전체 제한 시간이 아닙니다.

    내부 순서. 물체 점군을 POINT_CLOUD 입력으로 설정하고 그리퍼 이름·후보 생성 수·top_k를 함께 전송합니다. 반환 액션의 성공 여부뿐 아니라 메시지가 OK:로 시작하는지와 후보 존재 여부를 확인합니다.

    결과의 의미. 성공은 모델 후보를 얻었다는 뜻이며 로봇의 도달 가능성을 보장하지 않습니다. 점수가 높은 후보라도 TCP 변환·충돌·손목 제약에서 탈락할 수 있습니다. BT는 이 단계에서 후보 하나를 확정하지 않으며, 최종 선택은 SelectFeasibleGrasp가 담당합니다.

    파지 선택·실행¶

    SelectFeasibleGrasp¶

    방향 포트 의미
    입력 capture, mask, cloud, candidates 동일 촬영에서 얻은 관측·모델 후보
    입력 use_estimated_width=false true이면 점군 기반 폭 추정
    선택 입력 pregrasp_distance 0.02~0.20m; 생략 시 YAML (현재 0.10m)
    선택 입력 lift_distance 0.065~0.20m; 생략 시 YAML (현재 0.08m)
    출력 selected_plan shared_ptr<GraspPlan>: 후속 plan 포트에 연결
    출력 pregrasp, grasp_pose TcpPose: base 좌표계의 사전 접근·최종 TCP 목표
    출력 grasp_width, close_width 관측 폭·명령 폭(m). 고정 폭 모드의 관측 폭은 0
    1. 관측 나이 30초 이내, 촬영 후 arm 관절 변화 0.02rad 이내인지 검사합니다. 마스크·점군·후보의 frame/stamp와 실제 마스크·깊이에서 재투영한 점군의 일치도 확인합니다.
    2. 촬영 시각 TF로 점군을 base로 변환하고 주변 깊이로 수평 지지면을 추정합니다. 대상 AABB 박스를 등록하고 대상과 두 손가락의 접촉을 허용합니다. Octomap 사용 시 대상 영역을 제외하고 지도를 다시 확인합니다.
    3. 모델 자세와 180° 대칭 자세를 만들고, 설정에 따라 현재 TCP와 회전 차이가 작은 순서로 검사합니다.
    4. 하향 각도·대상 경계·선택적 높이·지지면 여유를 검사합니다. 폭 추정 모드에서는 모델의 손가락 닫힘 축으로 점군 폭을 계산합니다.
    5. 사전 접근 IK → 접근 Cartesian → 리프트 Cartesian → 사전 접근 OMPL 경로를 검사합니다. 손목 제약과 반환 경로의 목표 관절값도 확인하고 첫 통과 후보를 선택합니다.

    직접 호출: TF, /compute_fk, /compute_ik, /compute_cartesian_path, /plan_kinematic_path, /get_planning_scene, /apply_planning_scene. Octomap 사용 시 /clear_octomap과 sim의 /simulation/set_grasp_region 또는 real의 /grasp/set_grasp_region도 호출합니다. 선택 중에는 팔·그리퍼를 실행하지 않습니다. 모두 탈락하면 사유별 횟수와 함께 실패합니다.

    최종 TCP는 base_T_camera × camera_T_model_grasp × model_T_tcp로 계산합니다. 사전 접근은 모델 접근축 반대 방향으로 떨어진 위치이고, 리프트는 base +Z 방향입니다. 추정 폭 모드의 닫기 폭은 관측 폭에서 grasp_width_closing_inset을 빼고 최대 열림 폭으로 제한합니다. inset 허용 범위는 0~0.005m, 현재 값은 0.005m입니다. 고정 폭 모드는 현재 gripper_close_width=0.04m를 사용합니다.

    계획 객체에 저장되는 것. 선택한 관측, 사전 접근·최종 TCP 자세, 실행할 사전 접근 궤적, 손목 제약, 관측 폭·명령 폭, 리프트 거리를 하나의 GraspPlan에 담습니다. 접근·리프트의 사전 검사 궤적은 실행 가능성 확인용이며, 실제 실행 노드에서는 현재 상태로 다시 계산합니다. pregrasp·grasp_pose·폭 출력은 조회·사용자 트리용이고, 후속 기본 모션 노드는 plan 안의 값을 사용합니다.

    후보 탈락과 요청 실패. not_top_down, off_target, height, table_clearance, invalid_observed_width, pre_ik, wrist_goal, approach_path, lift_path, pre_plan은 후보별 탈락 집계입니다. 반면 오래된 촬영·점군 불일치·지원면 추정 실패·서비스 예외는 선택 작업 자체를 실패시킵니다. 첫 통과 후보를 선택하므로 모든 실행 가능 후보를 평가해 전역 최적 경로를 고르는 방식은 아닙니다. 장면·충돌 허용은 변경하지만 궤적 실행은 하지 않습니다.

    MoveToPregrasp¶

    • 입력: plan, 필요 상태 SELECTED.
    • 기능: 선택한 계획인지와 촬영 유효성을 다시 검사한 뒤 저장된 사전 접근 경로를 실행합니다.
    • 직접 호출: /execute_trajectory. 새 OMPL 계획을 만드는 단계가 아닙니다.
    • 완료 시 PREGRASP가 됩니다. 실제 시작 관절값이 계획과 크게 다르면 실행을 거부합니다.

    내부 순서. 전달받은 포인터가 현재 선택 계획과 같은지, 단계가 SELECTED인지 확인합니다. 촬영 유효성을 다시 검사하고, 저장된 궤적의 시작 관절값과 현재 피드백 차이가 0.20rad를 넘으면 거부합니다. 이후 ExecuteTrajectory 결과와 최종 관절 피드백을 확인하고 PREGRASP로 바꿉니다.

    사용 시점. 후보 선택 이후 로봇을 수동으로 움직였다면 저장 경로를 그대로 쓰지 말고 다시 관측·선택해야 합니다. 이 노드에 다른 목표 자세를 추가 입력해 저장 계획을 덮어쓰는 기능은 없습니다.

    ApproachGrasp¶

    • 입력: plan, 필요 상태 PREGRASP.
    • 기능: 현재 상태에서 최종 grasp_pose까지 Cartesian 경로를 다시 계획·실행합니다.
    • 직접 호출: /compute_cartesian_path, /execute_trajectory.
    • 성공 코드·경로 fraction ≥0.999·궤적 유효성·선택된 손목 제한을 요구합니다. 완료 시 APPROACHED가 됩니다.

    내부 순서. PREGRASP를 확인하고 최신 시작 상태에서 저장된 최종 TCP까지 Cartesian을 요청합니다. 경로 코드·fraction·관절값·손목 제약을 확인한 후 실행하고, 피드백으로 도달을 확인하면 APPROACHED가 됩니다.

    실패 시 동작. 접근은 부분 Cartesian 경로를 실행하지 않고 실패합니다. MovePlace와 달리 OMPL 우회 계획으로 대체하지 않으므로 파지 접근축의 직선 동작을 유지합니다. 그리퍼 닫기는 다음 노드이므로 이 단계의 성공만으로 대상이 부착되지 않습니다.

    AttachObject¶

    • 입력: plan, 필요 상태 APPROACHED.
    • 기능: 계획에 저장한 close_width와 YAML의 gripper_close_duration (현재 2초)으로 닫고, 대상 박스를 TCP에 부착된 충돌 물체로 등록합니다.
    • 직접 호출: /gripper_controller/follow_joint_trajectory, /apply_planning_scene.
    • 접촉 허용 링크는 gripper_link1, gripper_link2, TCP입니다. 완료 시 ATTACHED가 됩니다.
    • 닫기를 시작한 뒤 실패하면 잡힘 여부가 불명확하므로 자동으로 열거나 대상 형상을 제거하지 않습니다. 부착은 계획상의 가정이며 실제 잡힘 성공을 판정하지 않습니다.

    내부 순서. APPROACHED를 확인한 뒤, 닫기를 시작하기 전에 내부 attached를 먼저 설정합니다. 닫기 액션 성공 후 대상 충돌 박스를 TCP에 부착하고 release_ready=false, 계획 단계를 ATTACHED로 갱신합니다.

    닫기 판정의 한계. 닫기 명령은 개방과 달리 목표 간격에 대한 5mm 피드백 도달 검사를 하지 않습니다. 물체 접촉으로 목표 폭에 도달하지 못할 수 있기 때문이며, 액션 성공을 잡힘 센서로 해석하면 안 됩니다. 닫기 중단·장면 부착 실패 시에도 자동 개방하지 않고, 실제 부착이 없는데 내부 부착만 남은 경우 후속 이동의 상태 검사에서 거부합니다.

    LiftObject¶

    • 입력: plan, 필요 상태 ATTACHED와 유지된 부착 정보.
    • 기능: 현재 TCP의 FK를 구하고 선택 때 저장한 lift_distance만큼 base +Z 목표를 생성합니다. 부착 형상을 포함해 Cartesian 경로를 다시 검사·실행합니다.
    • 직접 호출: /compute_fk, /compute_cartesian_path, /execute_trajectory.
    • 접근과 같은 완전성·손목 제한 검사를 수행합니다. 완료 시 LIFTED입니다.

    내부 순서. 계획 단계 ATTACHED와 내부 부착 상태를 확인한 뒤 현재 TCP를 FK로 얻습니다. 그 위치에서 base +Z로 저장된 리프트 거리만큼 올라가는 목표를 만들어 Cartesian을 계획·실행합니다. 실제 시작 위치를 기준으로 하므로 선택 시의 최종 자세를 그대로 절대 목표로 재사용하지 않습니다.

    완료와 실패. 궤적 실행·관절 도착 확인 후 LIFTED로 바뀝니다. 부분 경로·손목 제약 위반·실행 실패는 모두 실패이며, 실패해도 부착과 닫힘을 유지합니다. 이 노드는 home 복귀까지 수행하지 않으므로 XML 뒤에 복귀 노드를 별도로 둡니다.

    배치·해제¶

    MovePlace¶

    • 입력: x, z, 선택적 home_joint_positions. X·Z는 0~0.30m이며 생략 시 0입니다.
    • 조건: 부착된 대상이 있고 home 허용 오차 안이어야 합니다.
    • 기능: home TCP에서 base X·Z 오프셋을 적용한 목표로 이동합니다. 먼저 Cartesian을 계획하고, 정상 응답의 부분 경로이면 같은 목표에 대해 충돌 검사 IK와 OMPL 관절 경로를 시도합니다.
    • 직접 호출: Planning Scene 확인, /compute_fk, /compute_cartesian_path, 필요 시 /compute_ik, /plan_kinematic_path, 이후 /execute_trajectory.
    • 완료 시 release_ready=true로 표시합니다. 실패하면 부착·닫힘 상태를 유지합니다.

    내부 순서. 진입할 때 release_ready=false로 초기화하고 장면·전송을 확인합니다. home 관절의 FK 위치에 X·Z를 더한 목표를 만들며 방향은 home TCP 방향을 유지합니다. 정상적인 Cartesian 응답의 fraction이 0.999 이상이면 실행하고, 그보다 작은 부분 경로일 때만 같은 목표의 IK·관절 계획으로 대체합니다.

    완료와 실패. 실행과 피드백 도착 확인까지 성공해야 release_ready=true가 됩니다. 잘못된 응답·IK 실패·실행 실패는 대체 성공으로 취급하지 않으며 물체를 유지합니다. Y 입력은 없고, placement 요청마다 새 모델 추론을 수행하지 않습니다.

    ReleaseObject¶

    • 입력: 선택적 opening (0~0.10m), duration (0.001~30초).
    • 조건: 대상 부착과 성공한 MovePlace의 release_ready가 필요합니다.
    • 기능: 그리퍼를 열고 피드백으로 확인한 뒤 부착 해제, 대상·임시 충돌 허용·점군 제외 영역을 정리합니다.
    • 직접 호출: Planning Scene 확인, /gripper_controller/follow_joint_trajectory, /apply_planning_scene, /get_planning_scene, Octomap 사용 시 대상 제외 서비스.
    • 기본값은 OpenGripper와 같습니다. 임의 위치에서 물체를 놓는 범용 노드가 아닙니다.

    내부 순서. 실제 장면의 부착 상태를 확인하고 배치 완료 플래그를 검사합니다. 개방 액션과 실제 간격 도달을 확인한 다음 장면에서 부착을 제거하고 내부 부착·배치 플래그를 내립니다. 이어서 대상 형상, 변경했던 충돌 허용 쌍, 활성화된 점군 제외 영역을 정리합니다.

    실패를 해석할 때. 개방 확인 전에 실패하면 부착 해제 단계로 진행하지 않습니다. 개방 이후 장면 갱신·정리가 실패하면 물리 상태와 계획 장면이 다를 수 있으므로 성공으로 보고하지 않습니다. CheckGraspReady release_previous=true는 공통 release 로직의 별도 허용 경로이고, 일반 ReleaseObject는 MovePlace 성공 조건을 생략할 수 없습니다.

    계획 상태와 공통 동작¶

    selected_plan="{grasp_plan}"을 후속 노드의 plan="{grasp_plan}"으로 연결합니다. 단계 상태는 SELECTED → PREGRASP → APPROACHED → ATTACHED → LIFTED입니다. 다른 계획·단계 생략·이미 실행한 단계의 재실행은 거부합니다. 문자열 plan_id나 서버 세션은 사용하지 않습니다.

    모션은 비동기 BT 작업으로 수행하며 진행 중에는 RUNNING을 반환합니다. 서로 다른 BT 분기에서 동시에 같은 로봇을 명령하면 거부합니다. halt는 진행 중 작업과 액션을 취소합니다. 미부착 실패는 장면을 정리하고, 닫기 시작 후·부착 후 실패는 자동 개방하지 않습니다.

    모션 설정은 bt_navigator.ros__parameters.bt_motion, 인식 설정은 bt_perception입니다. XML 입력은 해당 호출에만 적용되고 YAML 기본값을 바꾸지 않습니다. 모션 노드에는 중계용 server_name·server_timeout이 없습니다.

    Groot와 이전 XML¶

    노드 정의는 node_models/rwh_beyond_tree_nodes.xml입니다. 실행 XML과 별개이며 다음 명령으로 재생성합니다.

    ros2 run rwh_beyond_bt generate_tree_nodes_xml \
  /root/ros2_ws/src/rwh_beyond/rwh_beyond_bt/node_models/rwh_beyond_tree_nodes.xml

    기존 XML의 SelectFeasibleGrasp.plan_id 출력은 selected_plan으로, 후속 모션 노드의 plan_id 입력은 plan으로 바꿉니다. RunGraspStage·RunGraspStep 중계 액션은 제거됐습니다. 인식 입력은 capture·mask·cloud·candidates로 직접 연결합니다.
