    실물 PiPER 제어¶

    실물 runner piper_moveit은 공식 CAN driver, robot_state_publisher, MoveIt, 선택한 D405/D435, 계획용 점군 필터와 선택한 실행 transport를 시작합니다. bt_demo runner는 이를 의존 실행하고 BT와 모델 브릿지를 추가합니다.

    준비¶

    CAN을 준비하고 ros_runner/config/robot_real.yaml의 piper·realsense 설정을 확인합니다. 기본 CAN은 can0, 자동 활성화는 false, 실물 BT transport는 feedback입니다. 전체 항목은 Runner 장치 설정을 참고하세요.

    source /opt/ros/jazzy/setup.bash
source /root/ros2_ws/install/setup.bash
ros2 launch ros_runner runner.launch.py

    별도 터미널에서 실행합니다.

    ros2 service call /ros_runner/activate_bt_demo std_srvs/srv/Empty '{}'
ros2 topic echo /feedback/arm_status --once
ros2 topic echo /feedback/joint_states --once

    모터와 제어 모드¶

    모터 활성화와 명령 수신 gate는 별개입니다. 필요한 경우 사용자가 모터를 활성화합니다.

    ros2 service call /enable_agx_arm std_srvs/srv/SetBool '{data: true}'

    현재 driver 상태에서 ctrl_mode=1은 CAN 제어, 2는 티칭 모드입니다. 티칭에서 돌아올 때 필요한 서비스는 다음과 같습니다.

    ros2 service call /exit_teach_mode std_srvs/srv/Empty '{}'

    이 서비스는 현재 driver에서 home 이동과 모터 활성화도 수행할 수 있으므로 실제 이동 공간을 확보한 뒤 호출합니다. 실물 bt_demo runner는 기본적으로 활성화 10초 후 이 서비스를 한 번 호출합니다. 사용 여부·지연·시간 제한은 ros_runner/config/runners.yaml의 bt_demo_startup에서 설정합니다. 전환 후 arm status와 관절 피드백을 다시 확인하고 /run_demo를 호출합니다. 실물 trajectory transport는 실행 중 /control_enable gate를 관리합니다.

    실행 transport¶

    실물 BT runner는 feedback transport를 요구합니다. physical_trajectory가 FollowJointTrajectory를 받아 실제 joint feedback을 확인하며 명령을 전달합니다. 직접 piper_moveit.launch.py를 호출할 때는 기본값이 official이므로 실물 BT용이면 execution_transport:=feedback을 명시합니다.

    열기와 팔 이동은 실제 endpoint 확인을 사용합니다. 닫기는 설정한 폭을 현재 YAML의 2초 동안 명령한 뒤 완료하며 물체 잡힘은 판정하지 않습니다. 취소와 피드백 통신 오류는 별도로 처리합니다.

    시작 상태 허용 각도¶

    시작 허용 각도는 공통 rwh_beyond_bringup/config/bt_demo.yaml에서 관리합니다.

    bt_navigator:
  ros__parameters:
    bt_motion:
      planning_start_bounds_tolerance_deg: 10.0

    단위는 도이며 기본값은 10°입니다. 유효 범위는 0 초과~180°이며 내부에서 rad로 변환합니다. 장치 runner와 BT를 중지·재활성화하면 변경값이 적용됩니다. home_joint_tolerance(home 도착 판정, rad)와 physical_position_tolerance(동작 도착 판정, rad)는 같은 YAML의 별도 항목입니다. 시작 허용 각도를 변경해도 도착 판정값은 바뀌지 않습니다. URDF 한계를 이 범위 안에서 벗어난 관절만 계획용 복사본에서 경계값으로 보정합니다. 실제 피드백과 URDF 한계는 변경하지 않으며 큰 초과는 거부합니다. MoveIt 시작점 검사와 physical transport도 같은 허용량을 사용합니다. transport는 실측 상태에서 계획 시작점까지 연결 구간을 만들어 명령 점프를 줄입니다.

    계획 오류와 실행 오류를 구분해 확인합니다. 부분 Cartesian 경로는 그대로 실행하지 않습니다. 배치 이동만 같은 목표의 IK·OMPL 우회를 시도합니다. 팔·카메라의 충돌과 실제 장착 TF는 카메라 문서를 참고하세요.

    joint5 모델 범위와 저장 자세¶

    표준 PiPER의 joint5 모델·SDK·MuJoCo 범위를 ±75°(±1.308996938995747rad)로 맞췄습니다. AgileX 제품 사양은 ±75°를 안내하지만, 가져온 upstream URDF와 pyAgxArm 기본값은 ±70°여서 로컬 소스를 수정했습니다. 다른 PiPER 파생 모델의 범위와 컨트롤러 펌웨어 설정은 변경하지 않습니다.

    적용한 곳은 agx_arm_ros의 표준 PiPER URDF, moma-mj-lab의 대응 URDF·MuJoCo 관절/구동 범위, /root/robot_deps/pyAgxArm/pyAgxArm/api/constants.py의 표준 PiPER rad/degree 기본값입니다. 컨테이너에 설치된 pyAgxArm에도 같은 값을 반영했습니다. SDK를 원본 upstream 버전으로 재설치하면 제한값이 되돌아갈 수 있으므로 이 소스 변경을 함께 유지합니다. MoveIt의 공통 joint_limits.yaml은 속도·가속도만 설정하므로 위치 범위는 이 URDF를 따릅니다.

    이미 실행 중인 노드는 이전 모델·SDK 값을 메모리에 보관합니다. 현재 BT 작업을 종료하고 piper_moveit → bt_demo 순서로 재시작해야 새 제한이 적용됩니다. 실행 중인 MuJoCo도 새 모델을 읽으려면 재시작합니다. 저장된 front/left/right 관절값은 자동으로 변경하지 않습니다.

    저장 자세가 모델 범위를 넘으면 MoveIt이 제한 경계에 도달하는 경로를 반환해 BT의 목표 일치 검사에서 거부될 수 있습니다. 이 검사를 완화하거나 충돌 검사를 끄는 방식으로 처리하지 않습니다.
