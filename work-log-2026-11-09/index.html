PiPER MoveIt integration work log — 2026-11-09¶

Goal¶

Use the VCS-managed AgileX PiPER sources from the shared ROS 2 workspace through rwh_beyond, and make both the hardware and MuJoCo MoveIt stacks selectable by ros_runner.

Changes¶

  • Added rwh_beyond_bringup/launch/piper_moveit.launch.py.
  • Includes the official agx_arm_ctrl/start_single_agx_arm_moveit.launch.py.
  • Pins arm_type:=piper; forwards CAN port, end-effector, enable, speed, feedback, and control-gate arguments.
  • This is the hardware path: it starts the CAN PiPER driver and MoveIt. It does not start MuJoCo.
  • Added agx_arm_ctrl as an rwh_beyond_bringup runtime dependency.
  • Added mutually exclusive runner entries:
  • piper_moveit: hardware PiPER plus official MoveIt.
  • piper_moveit_sim: MuJoCo PiPER plus MoveIt and RViz.
  • Configured the MuJoCo MoveIt launch to use OMPL as the only default planning pipeline. CHOMP rejected a valid gripper start state in RViz.
  • Increased MuJoCo-only execution duration and goal-duration allowance for GUI physics timing.

Commands¶

# Hardware: CAN driver + MoveIt
ros2 service call /ros_runner/activate_piper_moveit std_srvs/srv/Empty '{}'

# Simulation: MuJoCo + MoveIt + RViz
ros2 service call /ros_runner/activate_piper_moveit_sim std_srvs/srv/Empty '{}'

The two runners deactivate one another before starting.

Validation¶

  • Built rwh_beyond_bringup and moma_bringup.
  • Verified the PiPER wrapper and MuJoCo simulation launch argument surfaces.
  • Verified that ros_runner accepts both PiPER runner definitions.

Gripper execution finding¶

The official PiPER driver publishes the physical gripper width and force through /feedback/joint_states: gripper.position is width in meters and gripper.effort is force in newtons. It also accepts gripper force in /control/joint_states.

MoveIt's stock FollowJointTrajectory completion is position-based. A gripper closing onto an object can therefore report GOAL_TOLERANCE_VIOLATED even when the fingers apply a valid holding force. A behavior-tree gripper action should evaluate the PiPER force feedback for grasp success instead of relying solely on the MoveIt trajectory result.
